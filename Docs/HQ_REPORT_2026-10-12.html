Security as built

  • TLS 1.2 with the PC certificate pinned by SHA-256 fingerprint; there is no fallback that skips the check.
  • First pairing uses a commit-then-reveal six-digit code that the user confirms on both PC and headset. Nothing is automatic; cancel, mismatch or timeout stores nothing.
  • Reconnect proves identity with an HMAC challenge using a per-device secret. The headset refuses to answer a PC whose identity changed.
  • Honest limit: on the headset the secret is a private file in the app's own storage, not the Android Keystore. Someone who roots the headset could read it. Keystore wrapping is a known hardening step, not done.

Decisions for HQ

  • Promote develop to main? Frame tests have passed. Recommended yes.
  • Model licenses: the bigger Depth Anything V2 models (Base, Large) are non-commercial, so they were not used. Depth Anything 3 Small and Base are Apache-2.0. Large and Giant are non-commercial. Stay on the Apache models for any product.
  • How the headset app reaches customers. The app is a developer build that is not in the Frame's menu, and today it is installed and started from the PC over adb. The proposal is for the PC app to be the companion that installs, updates and launches it (an Install or Update button is next). This depends on the customer's Frame allowing developer mode and network adb, and on adb's redistribution terms. Valve's own distribution route for third-party apps has not been checked yet and would replace this if it exists.
  • Keystore hardening for the device secret before any wider release.
  • Distribution: installer for the PC app (currently a 155 MB single-file exe plus helper) and how headset builds reach users. Neither exists yet.
