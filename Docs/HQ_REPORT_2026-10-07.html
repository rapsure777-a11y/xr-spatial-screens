XR SPATIAL SCREENS · SPATIAL CROP · 7 OCT 2026

Real-room passthrough works. Streaming works. Interaction is next.

The product goal is floating, cropped, clickable PC windows over the user's real room in full colour on the Steam Frame. A PC app streamed through SteamVR cannot get passthrough. A native app on the headset can. Two proofs on the real hardware (Steam Frame, Arcturus Vision Camera attached) now back that up.

Architecture

A PC host captures windows (Windows.Graphics.Capture), encodes them and applies input with SendInput. A native Unity/OpenXR client on the headset owns placement, cropping, layouts and the palette, shows each window as a panel, and sends pointer events back. About 80% of the existing C# carries over (math, layouts, placement, cropping, palette, click mapping). The Win32 half of input forwarding stays on the PC where it is already tested.

Risks and unknowns

  • JPEG at ~25 Mbit/s per window will not scale to several large windows. Production needs hardware H.264/H.265.
  • Only one small window and one source rate were tested. A 3440×1440 window, several windows and a heavy game running together are unmeasured.
  • The stream currently rides an adb tunnel on loopback. A real build needs a LAN connection with a pairing code and encryption.
  • Behaviour with the Arcturus camera unplugged was not tested.
  • Deployment depends on Lepton Development on the Frame and adb over IPv4; the frame hostname resolves to IPv6 and fails. Valve's devkit client or Frameloader are alternatives, not yet tried.
  • Valve documentation for the headset-side tools is thin; some behaviour was found by experiment.

Gate 3 plan, in small steps

  • 3a Frame controllers and a laser pointer in the headset app. One streamed window, click, drag and scroll forwarded to the PC.
  • 3b Bring in placement, 4-corner editing, cropping and the palette from the PC code base.
  • 3c Window list from the PC, saved layouts per app.
  • 3d Pairing code and LAN transport; H.264 when several windows are open.

Each step ends with a short headset check by the user.
