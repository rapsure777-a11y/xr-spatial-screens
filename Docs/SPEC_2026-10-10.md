Companion docs: `RESUME_2026-10-09.md` (commands and hazards), `SBS_STEREO.md`, `CONTROLLER_POLISH.md`, `PANEL_SIZING.md`, `DEPTH_LAB_UPDATE_2026-10-08.md`, `PERF_SOURCE_STARTUP_2026-10-10.md`.

## 1. Product in one paragraph
A native Android/OpenXR app (Unity 6000.3.9f1, URP, OpenXR 1.18) for the Steam Frame. A Windows PC host (`Tools/XrssStream`) captures chosen windows or monitors and streams them as JPEG over TCP, through adb on the dongle link (10.35.78.1:5555). The headset shows each capture as a freeform quad ("screen") placed in the room over passthrough. The user draws four corners with a controller, grabs, tilts, resizes and crops screens, and clicks, drags and types into the PC window through them. PC audio is played in the headset. Layouts are saved per application. Optional modes per screen: Depth Lab (2.5D) and SBS stereo (3D video).

## 2. Architecture
- **PC side:** `Tools/XrssCapture` (Windows.Graphics.Capture, .NET 8) and `Tools/XrssStream` (host: capture, JPEG encode, per-stream sizing, input injection, audio, supervisor, launchers). Started by `Experiments/Gate1Passthrough/host.ps1`.
- **Headset side (Assemblies):** `Core` (pure maths: QuadMath, PanelSizing, PanelTilt, StereoMath, StreamMath, Layout, GlbModel), `Capture` (backends, ScreenSource, network protocol, JPEG decode, remote audio), `Spatial` (SpatialWorkspace, PanelView, SurfaceTool, InputForwarder, DepthLab), `App` (SpatialApp, palette, keyboard, pointer sources, layout backup, perf log), `XR` (controller render-model feature), `Editor` (headset build and automation).
- **Rendering:** shader `XrSpatial/Panel`: projective per-pixel mapping on a quad (correct under any tilt), crop rectangle, optional `_SBS` keyword. One mesh and one draw per screen.
- **Persistence:** JSON layout per app key in the app's data folder, atomic write, mirrored to the PC (`%LOCALAPPDATA%\XrSpatialScreens\layout-backup`) so a reinstall can restore it. Old layout files stay loadable (new fields default).

## 5. Known limits and risks
- The right-eye SBS path cannot be tested on a PC (a desktop camera is always eye 0).
- Panel shape is not changed automatically when switching 3D mode (the user must press Fit picture). The user declined auto-reshape for now.
- Crop is refused on a screen already in a 3D mode: crop on a Flat screen first, then turn 3D on.
- SBS convergence is deliberately tiny (+-1%); larger shifts cause eye strain.
- The link depends on the Steam Frame dongle connection through adb; it drops, and `adb connect` is needed again.
- The Steam system "two people" overlay is not from this app (system feature).
- A layout silently accumulating sources made the app stutter (fixed). There is still no visible list of sources or named layouts, so similar build-up is possible for other settings.
- Capture is a CPU copy and absolute-pointer only (no raw mouse for FPS-style games). Windows larger than 3840x2160 are rejected.
- A Lepton/device reset wipes the app and its layout (the PC backup can restore it).
- HEVC hardware video and LAN pairing exist only on `claude/hardware-video` and are not in the main line.
- Passthrough background uses the compositor's blend mode; no custom passthrough features.

## 6. Branches
`main` and `develop` are old. `claude/integration-depth` is the working line (all of the above). Feature branches (`claude/sbs-stereo`, `claude/controller-polish`, and earlier gate branches) are already contained in it. `claude/hardware-video` is separate and deliberately excluded.

## 8. Decisions needed from HQ
- Is the target a personal tool or a product? Pairing, installers and LAN streaming are only worth building for a product.
- Priority between 3D video comfort features (SBS), Depth Lab, and productivity features (layouts, shortcuts).
- Whether HEVC and LAN (`claude/hardware-video`) should come into the main line.
- Approval to promote the integration line to `main`.
